# Third-party notices

I2Console is GPL-3.0-or-later and the ESP-IDF component under
`examples/esp-idf/components/i2console/` is LGPL-3.0-or-later, but the firmware
does not consist only of our own code. This file lists what else is in it and
under which terms. All of it is GPL-compatible.

The per-file notices in the sources are authoritative; this is a summary so the
situation is visible without reading every header.

## In this repository

### `src/font16.c`, `src/fonts.h`

STM32 LCD font tables from STMicroelectronics' STM32xx-EVAL board support code.

- Copyright (C) 2014 STMicroelectronics
- BSD-3-Clause, reproduced in full in both file headers
- `font16.c` is compiled into the firmware; `fonts.h` is included by it and by
  `src/lcd_driver.c`

Two consequences worth knowing:

- They are **excluded from `clang-format`** through `.clang-format-ignore`, so
  a future update from upstream stays a readable diff.
- `fonts.h` is **not UTF-8**. It carries 54 bytes of GB2312-encoded Chinese
  comments from the Waveshare example lineage, for example
  `最大字体微软雅黑24 (32x41)`. It is left byte-for-byte as it arrived rather
  than re-encoded, because rewriting vendored bytes to satisfy our own style
  rule would make the next upstream comparison harder for no functional gain.
  `.editorconfig` exempts it explicitly. Note that `grep` treats the file as
  binary because of this and will skip it silently unless given `-a`; that is
  how its copyright header escaped an earlier audit of this repository.

## Pulled in by the build

### `pico-sdk` (git submodule)

- Raspberry Pi Ltd, BSD-3-Clause, `pico-sdk/LICENSE.TXT`
- Pinned by submodule commit; the version in use is recorded in the SBOM
  attached to every release

### TinyUSB

- Copyright (c) 2018 hathach (tinyusb.org), MIT
- Vendored inside the pico-sdk at `pico-sdk/lib/tinyusb`, linked through the
  `tinyusb_device` and `tinyusb_board` targets

The pico-sdk also ships BTstack, the cyw43 driver, Mbed TLS and lwIP. This
firmware's link line does not reference them, so they are present in the
checkout but not in the binary. The SBOM generator reads the actual link line
rather than assuming, so those libraries are named only if that ever changes.

## Where to check this

Every release carries an SPDX SBOM per payload, generated by
`scripts/release/generate-sbom.py`, naming the repository commit, the pico-sdk
commit, TinyUSB and the compiler that built it.
